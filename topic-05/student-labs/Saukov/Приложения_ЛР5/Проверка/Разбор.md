# Результаты проверки для ЛР № 5

## Воспроизводимость

- Задача — подсчёт очков в боулинге. Точное условие одинаково во всех трёх файлах в [prompts](../prompts), начиная со строки «ЗАДАЧА». Для сравнения использованы девять исходных файлов из [answers](../answers), по одному на пару «модель × промпт».
- Набор проверок — [31 тест Exercism](https://github.com/exercism/python/blob/main/exercises/practice/bowling/bowling_test.py). SHA-256 локального [bowling_test.py](bowling_test.py) — `6b9a80b6835828f575ce0aba66876850f75c59f764014ac509fe1df7e3a9ee20`. Контрольная сумма совпадает с указанной в методичке.
- Окружение — Windows, Python 3.11.18, pytest 9.2.0, Radon 6.0.1, Pylint 4.1.4 и Astroid 4.3.4. В примере авторов использован Python 3.11.0.
- Каждый ответ скопирован без изменений под именем `bowling.py` в отдельную временную директорию. Для него выполнены `python -m pytest -q bowling_test.py`, `python -m radon cc -s -a -j bowling.py` и `python -m pylint --output-format=json2 bowling.py`. В ответах отсутствуют демонстрационные и тестовые функции. Глобальная переменная в GigaChat P1 участвует в работе программы и учтена в статическом анализе.
- TPR — доля пройденных тестов из 31. CC max — максимальная цикломатическая сложность метода. Таблица содержит также число ошибок, предупреждений, замечаний по рефакторингу и оформлению Pylint (E, W, R, C).
- Для повтора запустить `python check_bowling.py` с указанными версиями инструментов. Скрипт формирует [Метрики.csv](Метрики.csv) и [Протокол.json](Протокол.json). В протоколе сохранены вывод pytest, данные Radon и замечания Pylint для каждого ответа.

## Наблюдения для вывода

- ChatGPT и DeepSeek дали 31/31 при каждом промпте. У DeepSeek CC max снизилась с 18 до 16, а оценка Pylint выросла с 8,89 до 9,61. У ChatGPT самая низкая CC max у P2 (17), максимальный балл Pylint у P1 (9,42).
- GigaChat прошёл 23/31 с P0, 3/31 с P1 и 4/31 с P2. Оценка Pylint при этом выросла с 6,36 до 8,81 и 9,43. На P2 сбой в ведении состояния игры виден в тестах при оценке Pylint выше девяти.
- Средний TPR по трём моделям составил 91,40% для P0, 69,89% для P1 и 70,97% для P2. Из 279 проверок прошло 216. Сравнение описывает один ответ каждой модели на каждый промпт в одной задаче.
- Тесты на недопустимые действия принимают любое исключение с непустым сообщением. Например, GigaChat P0 отклоняет второй бонусный бросок в сценарии `[10, 5, 6]` из-за преждевременного завершения игры, поэтому соответствующий тест проходит даже при ошибке в обработке бонусов.

## Причины провалов

| Код | Версия | Провалов | Причина в коде |
| --- | --- | ---: | --- |
| A | GigaChat P0 | 7 | В 10-м фрейме после второго броска `pins < 10` закрывает игру как при спэре, так и при страйке с первым бонусом меньше 10. Допустимый третий бросок отклоняется ([строки 12–13 и 23–26](../answers/GigaChat_P0.py#L23)). |
| B | GigaChat P0 | 1 | Проверяется диапазон каждого броска. Сумма двух бросков за фрейм не проверяется, поэтому `5 + 6` принимается ([строки 7–22](../answers/GigaChat_P0.py#L7)). |
| C | GigaChat P1 | 27 | `score()` устанавливает общий для всех экземпляров `score_called` до проверки завершённости игры. Следующие тесты падают уже на первом броске нового экземпляра ([строки 33–34 и 90–94](../answers/GigaChat_P1.py#L90)). |
| D | GigaChat P1 | 1 | `score()` трактует более десяти бросков как лишние при открытом 10-м фрейме. Обычная игра из двадцати бросков отклоняется ([строки 103–106](../answers/GigaChat_P1.py#L103)). |
| E | GigaChat P2 | 26 | Первый бросок без страйка добавляется дважды, в `_check_roll_valid()` и в `roll()`. Один бросок закрывает фрейм, и следующие допустимые броски преждевременно отклоняются из-за достижения лимита фреймов ([строки 37–45, 65–80 и 26–27](../answers/GigaChat_P2.py#L37)). |
| F | GigaChat P2 | 1 | Из-за двойной записи первого броска 5 уже закрывает фрейм. Следующие 6 попадают в новый фрейм и проверка суммы двух бросков пропускает ошибку ([строки 37–55 и 65–80](../answers/GigaChat_P2.py#L37)). |

Для GigaChat P1 проверка `test_two_rolls_in_a_frame_cannot_score_more_than_10_points` изолированно проходит. Если сначала запустить в том же процессе `test_an_unstarted_game_cannot_be_scored`, проверка падает при первом допустимом броске. Проверка игры из двадцати нулей изолированно падает в `score()` по причине D. TPR в таблице рассчитан по общему прогону всех 31 теста.
