# Лабораторная работа. Генерация UML с помощью LLM

## Условие для обоих запросов

R1 · Клиент подает заявку с камерой, началом и концом интервала.
R2 · Если подтвержденная бронь той же камеры пересекает интервал, система отказывает с причиной. Иначе создает подтвержденную бронь.
R3 · Клиент видит свои брони и может отменить свою подтвержденную бронь.
R4 · Сотрудник проката видит все брони.
R5 · У камеры есть серийный номер и модель. У клиента есть ФИО и почта.
R6 · Каждая бронь относится к одной камере и одному клиенту. У каждой камеры и каждого клиента может быть несколько броней.
R7 · Интервал корректен, если начало раньше конца. Соседние интервалы могут соприкасаться.
R8 · Отмена сохраняет запись. Отмененная бронь не блокирует интервал.

## P0

По условию построй диаграммы вариантов использования, классов, последовательности подачи заявки и состояний брони. Выдай отдельный полный блок PlantUML для каждой диаграммы.

[Вставьте условие R1–R8 целиком.]

## P1

По условию построй диаграммы вариантов использования, классов, последовательности подачи заявки и состояний брони. Выдай отдельный полный блок PlantUML для каждой диаграммы.

Покажи границу системы и внешних акторов, кратности на обоих концах связей, ветки подтверждения и отказа, условие отмены. Сохраняй названия и статусы между диаграммами. Проверь, что заявка при отказе не создает бронь. Не вводи новые правила системы. Если нужны допущения, перечисли их отдельно. После кода сопоставь R1–R8 с конкретными элементами диаграмм или примечаниями.

[Вставьте условие R1–R8 целиком.]

## Проведение и отчет

Три LLM, по два новых чата в каждой. Фиксируйте модель, режим, дату, текст запроса и исходный ответ. Постройте каждый блок и зафиксируйте ошибки рендера до исправлений.

Для каждой пары модель–промпт сделайте строки R1–R8 со столбцами «требование», «диаграмма или строка кода», «выполнено / частично / не выполнено / не проверено», «обоснование». Отдельно перечислите придуманные правила и противоречия между диаграммами. Прогоните четыре мысленных сценария со слайда 17.

Сравните P0 с P1 внутри каждой модели, затем модели при одинаковом промпте. В отчет включите протокол, таблицы, примеры ошибок и выводы по кейсу. Приложите исходные ответы, блоки кода, рендеры или сообщения об ошибках. Исправленный комплект сдайте отдельно с перечнем исправлений.
