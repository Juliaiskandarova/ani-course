Вот четыре диаграммы по вашим требованиям. Каждая — в отдельном блоке PlantUML, готова к вставке в рендерер.

## 1. Диаграмма вариантов использования

```plantuml
@startuml
left to right direction
actor "Клиент" as Client
actor "Сотрудник проката" as Employee

rectangle "Система проката камер" {
  usecase "Подать заявку на бронь\n(камера, начало, конец)" as UC1
  usecase "Проверить корректность интервала\n(начало раньше конца)" as UC2
  usecase "Проверить пересечение\nс подтверждёнными бронями камеры" as UC3
  usecase "Создать подтверждённую бронь" as UC4
  usecase "Отклонить заявку с указанием причины" as UC5
  usecase "Просмотреть свои брони" as UC6
  usecase "Отменить свою\nподтверждённую бронь" as UC7
  usecase "Просмотреть все брони" as UC8
}

Client --> UC1
Client --> UC6
Client --> UC7
Employee --> UC8

UC1 ..> UC2 : <<include>>
UC1 ..> UC3 : <<include>>
UC3 ..> UC4 : <<extend>>\n(нет пересечений)
UC3 ..> UC5 : <<extend>>\n(есть пересечение)
UC7 ..> UC6 : <<include>>\n(бронь должна быть видна)
@enduml
```

Примечание: R8 отражается тем, что отмена — это переход состояния, а не удаление записи, поэтому отдельный вариант использования «Удалить бронь» не нужен.

## 2. Диаграмма классов

```plantuml
@startuml
skinparam classAttributeIconSize 0

class Клиент {
  - id : Long
  - фио : String
  - почта : String
}

class Камера {
  - id : Long
  - серийныйНомер : String
  - модель : String
}

class Бронь {
  - id : Long
  - начало : DateTime
  - конец : DateTime
  - статус : СтатусБрони
}

enum СтатусБрони {
  ПОДТВЕРЖДЕНА
  ОТМЕНЕНА
}

Клиент "1" -- "0..*" Бронь : подаёт >
Камера "1" -- "0..*" Бронь : относится к >

note on link
  R6: каждая бронь относится
  ровно к одной камере и одному клиенту
end note

note as N1
  R7: интервал корректен, если начало раньше конца;
  соседние интервалы [a, b] и [b, c] НЕ считаются пересекающимися
end note

note as N2
  R8: отмена сохраняет запись
  (статус ОТМЕНЕНА), но отменённая
  бронь не блокирует интервал
end note

Бронь .. N1
Бронь .. N2
@enduml
```

## 3. Диаграмма последовательности — подача заявки

```plantuml
@startuml
actor "Клиент" as Client
participant "Система проката" as Sys
participant "База данных" as DB

Client -> Sys : податьЗаявку(камера, начало, конец)

Sys -> Sys : проверить интервал:\nначало раньше конца? (R7)

alt Интервал некорректен
  Sys --> Client : отказ: причина "начало не раньше конца"
else Интервал корректен
  Sys -> DB : найти подтверждённые брони камеры,\nпересекающиеся с [начало, конец]
  DB --> Sys : список пересечений

  alt Пересечение найдено
    Sys --> Client : отказ: причина "интервал занят\n(номера конфликтующих броней)"
  else Пересечений нет
    Sys -> DB : создать бронь (камера, клиент, начало, конец,\nстатус = ПОДТВЕРЖДЕНА)
    DB --> Sys : бронь сохранена
    Sys --> Client : успех: бронь подтверждена (id брони)
  end
end
@enduml
```

## 4. Диаграмма состояний брони

```plantuml
@startuml
[*] --> Рассматривается : подана заявка (камера, начало, конец)

Рассматривается --> Подтверждена : интервал корректен (R7)\nи нет пересечений (R2)
Рассматривается --> [*] : отклонена\n(некорректный интервал\nили пересечение) (R2)

Подтверждена --> Отменена : клиент отменил свою бронь (R3)
Подтверждена --> Подтверждена : блокирует интервал

Отменена --> [*] : запись сохраняется,\nинтервал не блокируется (R8)

Подтверждена : видна клиенту и сотруднику (R3, R4)
Отменена : запись хранится,\nно не блокирует интервал (R8)
@enduml
```

Пара проектных решений, на которые стоит обратить внимание: состояние «Рассматривается» вынесено явно, потому что по R2 заявка может быть и отклонена — тогда запись об отклонённой заявке либо не создаётся вовсе (как на диаграмме: отклонение ведёт в терминальное состояние), либо можно завести статус «Отклонена», если истории отказов нужно хранить. И «соседние интервалы соприкасаются» учтено в R7-примечании: пересечение проверяется как строгое `начало_нового < конец_существующей` и `конец_нового > начало_существующей`.

Если нужен вариант с добавлением состояния «Отклонена» (чтобы сохранять и отказы) или последовательность для отмены брони — скажите, дособеру.
