## 1. Диаграмма вариантов использования

```plantuml
@startuml
left to right direction

actor "Клиент" as Client
actor "Сотрудник проката" as Employee

rectangle "Система бронирования камер" {
  usecase "Подать заявку на бронь" as Submit
  usecase "Просмотреть свои брони" as ViewOwn
  usecase "Отменить свою подтвержденную бронь" as Cancel
  usecase "Просмотреть все брони" as ViewAll
}

Client -- Submit
Client -- ViewOwn
Client -- Cancel
Employee -- ViewAll

note right of Submit
  Клиент указывает камеру, начало и конец интервала.
end note

note right of Cancel
  Условие: клиент является владельцем брони,
  статус брони — «Подтверждена».
end note
@enduml
```

## 2. Диаграмма классов

```plantuml
@startuml
class "Клиент" as Client {
  ФИО : Строка
  почта : Строка
}

class "Камера" as Camera {
  серийныйНомер : Строка
  модель : Строка
}

class "Бронь" as Booking {
  начало : ДатаВремя
  конец : ДатаВремя
  статус : СтатусБрони
}

enum "СтатусБрони" as BookingStatus {
  Подтверждена
  Отменена
}

Client "1" -- "0..*" Booking : клиент
Camera "1" -- "0..*" Booking : камера

note right of Booking
  Корректный интервал: начало < конец.

  Интервалы A и B пересекаются, если
  A.начало < B.конец и B.начало < A.конец.

  При проверке пересечения учитываются только
  брони той же камеры со статусом «Подтверждена».
end note
@enduml
```

## 3. Диаграмма последовательности подачи заявки

```plantuml
@startuml
actor "Клиент" as Client
participant "Система бронирования камер" as System

Client -> System : Подать заявку на бронь (камера, начало, конец)

alt [начало >= конец]
  System --> Client : Отказ — начало должно быть раньше конца
else [начало < конец]
  System -> System : Проверить пересечение с подтвержденными\nбронями той же камеры

  note right of System
    Пересечение есть, если
    начало < бронь.конец и бронь.начало < конец.
  end note

  alt [есть пересечение]
    System --> Client : Отказ — интервал пересекается\nс подтвержденной бронью той же камеры
  else [пересечений нет]
    System -> System : Создать бронь (клиент, камера, начало, конец)\nсо статусом «Подтверждена»
    System --> Client : Бронь подтверждена
  end
end
@enduml
```

## 4. Диаграмма состояний брони

```plantuml
@startuml
state "Подтверждена" as Confirmed
state "Отменена" as Cancelled

[*] --> Confirmed : Создать бронь\n[интервал корректен и нет пересечения\nс подтвержденными бронями той же камеры]

Confirmed --> Cancelled : Отменить бронь [клиент является владельцем]\n/ сохранить запись со статусом «Отменена»

note right of Cancelled
  Запись сохраняется.
  Бронь не блокирует интервал.
end note
@enduml
```

**Допущение о представлении.** Заявка показана как вход операции «Подать заявку на бронь». Диаграмма состояний описывает жизненный цикл созданной брони.

**Проверка отказа.** Обе ветки отказа завершаются ответом клиенту с причиной. Единственная операция создания брони находится в ветке с корректным интервалом без пересечений.

| Требование | Элемент диаграммы |
|---|---|
| R1 | Вариант использования «Подать заявку на бронь» и первое сообщение последовательности с камерой, началом и концом. |
| R2 | Проверка пересечения с подтвержденными бронями той же камеры и ветки отказа с причиной либо создания брони со статусом «Подтверждена». |
| R3 | Варианты использования «Просмотреть свои брони» и «Отменить свою подтвержденную бронь». Переход из состояния «Подтверждена» разрешен владельцу брони. |
| R4 | Связь актора «Сотрудник проката» с вариантом использования «Просмотреть все брони». |
| R5 | Атрибуты `серийныйНомер` и `модель` у камеры, `ФИО` и `почта` у клиента. |
| R6 | Обе связи на диаграмме классов имеют кратность `1` со стороны клиента или камеры и `0..*` со стороны брони. |
| R7 | Проверка `начало < конец` и два строгих неравенства в условии пересечения. Равенство конца одного интервала началу другого допускается. |
| R8 | Переход в состояние «Отменена» сохраняет запись. Проверка пересечений учитывает только подтвержденные брони. |
