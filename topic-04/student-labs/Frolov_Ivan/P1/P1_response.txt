Диаграмма прецедентов

```plantuml
@startuml
title Диаграмма прецедентов. Система проката камер
left to right direction

actor "Клиент" as Client

rectangle "Система проката камер" {
  usecase "Подать заявку на бронирование" as UC1
  usecase "Просмотреть свои брони" as UC2
  usecase "Отменить свою подтвержденную бронь" as UC3
  usecase "Просмотреть все брони" as UC4
}

actor "Сотрудник проката" as Staff

Client --> UC1
Client --> UC2
Client --> UC3
Staff --> UC4
@enduml
```

Диаграмма классов

```plantuml
@startuml
title Диаграмма классов. Система проката камер

class Клиент {
  ФИО
  почта
}

class Камера {
  серийный номер
  модель
}

class Бронь {
  начало
  конец
  статус : СтатусБрони
}

enum СтатусБрони {
  Подтверждена
  Отменена
}

Бронь "0..*" -- "1" Клиент : относится к
Бронь "0..*" -- "1" Камера : относится к
Бронь ..> СтатусБрони : статус

note bottom of Бронь
  Экземпляр создается только при успешной заявке
  сразу со статусом «Подтверждена».
  Отказ заявки бронь не создает.
  Отмена сохраняет запись и меняет статус на «Отменена».
end note
@enduml
```

Диаграмма последовательности: подача заявки

```plantuml
@startuml
title Диаграмма последовательности: подача заявки. Система проката камер

actor "Клиент" as Client

box "Система проката камер" #White
  boundary "Система проката камер" as System
end box

Client -> System : Заявка(камера, начало, конец)

alt начало не раньше конца
  System --> Client : Отказ (причина: интервал некорректен,\nначало не раньше конца)
  note right of System : Бронь не создается
else есть подтвержденная бронь той же камеры,\nинтервал которой пересекает заявку\n(соприкосновение границ не является пересечением)
  System --> Client : Отказ (причина: пересечение\nс подтвержденной бронью этой камеры)
  note right of System : Бронь не создается
else интервал корректен и пересечения нет
  System -> System : Создать бронь(клиент, камера, начало, конец,\nстатус = Подтверждена)
  System --> Client : Подтверждение: бронь создана,\nстатус «Подтверждена»
end
@enduml
```

Диаграмма состояний брони

```plantuml
@startuml
title Диаграмма состояний брони. Система проката камер

[*] --> Подтверждена : успешная заявка\n(бронь создана)

Подтверждена --> Отменена : Отменить свою подтвержденную бронь\n[бронь принадлежит этому клиенту]

note right of Отменена
  Отмена сохраняет запись.
  Отмененная бронь не блокирует интервал.
end note

note as Rejected
  Отклоненная заявка не создает бронь
  и не приводит к состоянию брони.
  Статусы брони только: «Подтверждена» и «Отменена».
end note
@enduml
```

Допущения

1. На диаграмме последовательности сначала проверяется корректность интервала, затем пересечение с подтвержденными бронями. Требования задают обе проверки, но не фиксируют их порядок. При отказе на любой проверке бронь не создается.
2. Кратность «несколько броней» показана как `0..*`: требования не обязывают иметь хотя бы одну бронь у каждого клиента и каждой камеры.
3. Состав списка при просмотре требованиями не уточнен, поэтому прецеденты просмотра не содержат фильтра по статусу.

Соответствие требованиям

- **R1.** Прецедент «Подать заявку на бронирование»; сообщение последовательности `Заявка(камера, начало, конец)`; у класса «Бронь» атрибуты «начало» и «конец», связь с «Камера».
- **R2.** Ветки `else` последовательности: отказ с причиной при пересечении с подтвержденной бронью той же камеры; создание брони со статусом «Подтверждена» только в ветке успеха. Начальный переход диаграммы состояний в «Подтверждена». Примечания на обеих диаграммах: отказ бронь не создает.
- **R3.** Прецеденты клиента «Просмотреть свои брони» и «Отменить свою подтвержденную бронь». Переход «Подтверждена» → «Отменена» с условием `[бронь принадлежит этому клиенту]`.
- **R4.** Актор «Сотрудник проката» вне границы системы и прецедент «Просмотреть все брони» внутри «Система проката камер».
- **R5.** Класс «Камера»: серийный номер, модель. Класс «Клиент»: ФИО, почта.
- **R6.** Ассоциации `Бронь "0..*" -- "1" Клиент` и `Бронь "0..*" -- "1" Камера` с именем «относится к»: у брони ровно один клиент и одна камера, у клиента и камеры — несколько броней.
- **R7.** Ветка `alt` «начало не раньше конца» с отказом и причиной, без создания брони. В условии ветки пересечения указано, что соприкосновение границ пересечением не является.
- **R8.** Примечание состояния «Отменена»: запись сохраняется и не блокирует интервал. Проверка пересечения в последовательности учитывает только подтвержденную бронь. Отдельного уничтожения объекта нет.
