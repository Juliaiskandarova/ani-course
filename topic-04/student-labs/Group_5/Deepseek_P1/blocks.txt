title Диаграмма вариантов использования

actor "Клиент" as Client
actor "Сотрудник проката" as Employee

rectangle "Система бронирования камер" {
  usecase "Подать заявку на бронь\n(камера, начало, конец)" as Submit
  usecase "Проверить пересечение подтвержденных броней" as CheckOverlap
  usecase "Создать подтвержденную бронь" as CreateBooking
  usecase "Отказать с причиной" as Reject
  usecase "Просмотреть свои брони" as ViewOwn
  usecase "Отменить свою подтвержденную бронь" as Cancel
  usecase "Просмотреть все брони" as ViewAll
}

Client --> Submit
Client --> ViewOwn
Client --> Cancel
Employee --> ViewAll

Submit ..> CheckOverlap : <<include>>
CreateBooking .> Submit : <<extend>>\n[пересечения нет]
Reject .> Submit : <<extend>>\n[пересечение есть]

note right of Cancel
  Условие отмены:
  бронь принадлежит клиенту
  и имеет статус «Подтверждена»
end note

note bottom of Reject
  При отказе бронь не создается
end note

@enduml

@startuml
title Диаграмма классов

class Клиент {
  ФИО
  почта
}

class Камера {
  серийныйНомер
  модель
}

class Заявка {
  начало
  конец
  результат : Подтверждена | Отказана
  причинаОтказа
}

class Бронь {
  начало
  конец
  статус : СтатусБрони
}

enum СтатусБрони {
  Подтверждена
  Отменена
}

Клиент "1" -- "0..*" Заявка : подает
Камера "1" -- "0..*" Заявка : указывается в

Клиент "1" -- "0..*" Бронь : владеет
Камера "1" -- "0..*" Бронь : относится к

Заявка "0..1" -- "0..1" Бронь : создает при подтверждении

Бронь --> СтатусБрони

note right of Заявка
  R1: заявка содержит камеру, начало и конец интервала.
  При результате «Отказана» бронь не создается.
end note

note right of Бронь
  R2: бронь создается только при отсутствии пересечения.
  R8: отмена сохраняет запись; статус «Отменена» не блокирует интервал.
end note

@enduml

@startuml
title Последовательность подачи заявки

actor "Клиент" as Client

box "Система бронирования камер"
  participant "Система" as System
  participant "Хранилище броней" as Repo
end box

Client -> System : податьЗаявку(камера, начало, конец)

note right of System
  R7: предусловие — начало < конец.
  Пересечение проверяется строго:
  соседние интервалы могут соприкасаться.
end note

System -> Repo : найтиПодтвержденныеБрони(\n  камера,\n  интервал [начало, конец)\n)
Repo --> System : список пересечений

alt пересечение есть (R2)
  System --> Client : Отказ с причиной
  note right of System
    Бронь не создается.
    Вызов создатьБронь в этой ветке отсутствует.
  end note

else пересечения нет
  System -> Repo : создатьБронь(\n  клиент, камера, начало, конец,\n  статус = Подтверждена\n)
  Repo --> System : бронь
  System --> Client : Подтвержденная бронь
end

@enduml

@startuml
title Состояния брони

[*] --> Подтверждена : [пересечения нет]\nсоздана подтвержденная бронь

Подтверждена --> Отменена : [инициатор = клиент-владелец]\nотмена

Отменена --> [*]

note right of Подтверждена
  Блокирует интервал камеры.
end note

note right of Отменена
  R8: запись сохраняется;
  интервал не блокируется.
end note

note bottom of Подтверждена
  Отказ при пересечении:
  бронь не создается,
  состояние брони не возникает.
end note

@enduml
