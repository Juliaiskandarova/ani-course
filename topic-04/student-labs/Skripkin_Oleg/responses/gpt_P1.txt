## 1. Диаграмма вариантов использования

```plantuml
@startuml
left to right direction

actor "Клиент" as Client
actor "Сотрудник проката" as Employee

rectangle "Система бронирования камер" {
  usecase "Подать заявку" as Submit
  usecase "Проверить интервал" as Validate
  usecase "Проверить пересечение\nс подтвержденными бронями" as CheckOverlap
  usecase "Получить подтверждение\nи создать бронь" as Confirm
  usecase "Получить отказ\nс причиной" as Reject
  usecase "Просмотреть свои брони" as ViewOwn
  usecase "Отменить свою\nподтвержденную бронь" as Cancel
  usecase "Просмотреть все брони" as ViewAll
}

Client -- Submit
Client -- ViewOwn
Client -- Cancel
Employee -- ViewAll

Submit ..> Validate : <<include>>
Submit ..> CheckOverlap : <<include>>
Confirm ..> Submit : <<extend>>\n[интервал корректен;\nпересечения нет]
Reject ..> Submit : <<extend>>\n[интервал некорректен\nили есть пересечение]

note right of Submit
  Данные заявки: камера,
  начало и конец интервала.
end note

note right of Cancel
  Условие: бронь принадлежит клиенту
  и имеет статус «Подтверждена».
  Запись сохраняется.
end note

note bottom of CheckOverlap
  Учитываются только брони со статусом
  «Подтверждена». Соприкосновение
  границ интервалов — не пересечение.
end note

note bottom of Reject
  При отказе бронь не создается.
end note
@enduml
```

## 2. Диаграмма классов

```plantuml
@startuml
class Клиент {
  ФИО
  почта
}

class Камера {
  серийныйНомер
  модель
}

class Заявка {
  начало
  конец
}

class Бронь {
  начало
  конец
  статус: СтатусБрони
}

enum СтатусБрони {
  Подтверждена
  Отменена
}

class "Система бронирования камер" as System {
  +податьЗаявку(заявка: Заявка)
  +просмотретьСвоиБрони(клиент: Клиент)
  +отменитьБронь(клиент: Клиент, бронь: Бронь)
  +просмотретьВсеБрони()
}

class "Результат подачи заявки" as Result {
  подтверждениеИлиОтказ
  причинаОтказа
}

Клиент "1" -- "0..*" Заявка : подает >
Камера "1" -- "0..*" Заявка : указана в >
Клиент "1" -- "0..*" Бронь : имеет >
Камера "1" -- "0..*" Бронь : относится к <
Заявка "1" -- "0..1" Бронь : создает >
Заявка "1" -- "1" Result : завершается >
Бронь "0..1" -- "1" СтатусБрони : имеет >
System ..> Заявка
System ..> Бронь

note right of Заявка
  Корректный интервал: начало < конец.
end note

note right of Бронь
  Пересечение интервалов [a, b) и [c, d):
  a < d и c < b.
  Поэтому соседние интервалы могут соприкасаться.

  Подтвержденная бронь блокирует интервал.
  Отмененная бронь сохраняется, но не блокирует.
end note

note bottom of Result
  Если заявке отказано, связанной брони нет.
  Причина отказа указывается в результате.
end note
@enduml
```

## 3. Диаграмма последовательности подачи заявки

```plantuml
@startuml
actor "Клиент" as Client
boundary "Система бронирования камер" as System
database "Брони" as Store

Client -> System : податьЗаявку(камера, начало, конец)
activate System

alt начало >= конец
  System --> Client : отказ(причина: некорректный интервал)
else начало < конец
  System -> Store : найти подтвержденные брони\nтой же камеры, пересекающие интервал
  Store --> System : найденные брони

  alt есть пересечение
    System --> Client : отказ(причина: пересечение\nс подтвержденной бронью)
  else пересечения нет
    create "Бронь" as Booking
    System -> Booking : создать(клиент, камера,\nначало, конец, Подтверждена)
    System -> Store : сохранить(Booking)
    Store --> System : сохранено
    System --> Client : подтверждение(Booking)
  end
end

deactivate System

note over System, Store
  Пересечение: начало < конец существующей брони
  и начало существующей брони < конец.
  Отмененные брони не учитываются.
  В обеих ветках отказа бронь не создается.
end note
@enduml
```

## 4. Диаграмма состояний брони

```plantuml
@startuml
[*] --> Подтверждена : заявка подтверждена /\nбронь создана

Подтверждена --> Отменена : отменить [обращается владелец брони] /\nсохранить запись

note right of Подтверждена
  Блокирует свой интервал.
end note

note right of Отменена
  Запись сохраняется.
  Интервал не блокируется.
end note

note bottom of Подтверждена
  Отказ по заявке не является состоянием брони:
  при отказе бронь не создается.
end note
@enduml
```

### Допущение

- Для однозначного обозначения соприкосновения границ интервалы записаны как полуоткрытые `[начало, конец)`. Это не меняет правило R7: соседние интервалы не пересекаются.

### Соответствие требованиям

| Требование | Элементы диаграмм |
|---|---|
| R1 | «Подать заявку»; класс `Заявка`; первое сообщение диаграммы последовательности. |
| R2 | «Проверить пересечение», ветки подтверждения и отказа; связь `Заявка "1" -- "0..1" Бронь`; создание брони только в ветке «пересечения нет». |
| R3 | «Просмотреть свои брони», «Отменить свою подтвержденную бронь»; переход `Подтверждена --> Отменена`. |
| R4 | Актор «Сотрудник проката» и вариант «Просмотреть все брони». |
| R5 | Атрибуты классов `Камера` и `Клиент`. |
| R6 | Связи `Клиент "1" -- "0..*" Бронь` и `Камера "1" -- "0..*" Бронь`. |
| R7 | Примечание к `Заявка`, проверка `начало < конец` и формула пересечения. |
| R8 | Примечания к состоянию `Отменена` и классу `Бронь`; при поиске пересечений отмененные брони не учитываются. |
