# Диаграммы для системы проката камер

## 1. Диаграмма вариантов использования

```plantuml
@startuml UseCaseDiagram
left to right direction
skinparam packageStyle rectangle

actor "Клиент" as Client
actor "Сотрудник проката" as Employee

rectangle "Система проката камер" {
  usecase "Подать заявку на бронь" as UC1
  usecase "Просмотреть свои брони" as UC2
  usecase "Отменить свою бронь" as UC3
  usecase "Просмотреть все брони" as UC4
  usecase "Проверить пересечение интервалов" as UC5
  usecase "Создать подтвержденную бронь" as UC6
  usecase "Отказать с причиной" as UC7
  usecase "Проверить корректность интервала" as UC8
}

Client --> UC1
Client --> UC2
Client --> UC3
Employee --> UC4

UC1 ..> UC8 : <<include>>
UC1 ..> UC5 : <<include>>
UC5 <.. UC6 : <<extend>>\n[нет пересечения]
UC5 <.. UC7 : <<extend>>\n[есть пересечение]

note bottom of UC8
  R7: начало раньше конца.
  Соседние интервалы могут соприкасаться.
end note

note bottom of UC3
  R8: Отмена сохраняет запись.
  Отменённая бронь не блокирует интервал.
end note

@enduml
```

## 2. Диаграмма классов

```plantuml
@startuml ClassDiagram
skinparam classAttributeIconSize 0

class Клиент {
  - id : UUID
  - ФИО : String
  - email : String
  + податьЗаявку(камера, начало, конец) : Бронь
  + моиБрони() : List<Бронь>
  + отменить(бронь : Бронь) : void
}

class СотрудникПроката {
  - id : UUID
  - ФИО : String
  + всеБрони() : List<Бронь>
}

class Камера {
  - id : UUID
  - серийныйНомер : String
  - модель : String
  + getБрони() : List<Бронь>
}

class Бронь {
  - id : UUID
  - начало : DateTime
  - конец : DateTime
  - статус : СтатусБрони
  - причинаОтказа : String
  + корректныйИнтервал() : boolean
  + пересекается(интервал) : boolean
  + отменить() : void
}

enum СтатусБрони {
  ПОДТВЕРЖДЕНА
  ОТКАЗАНА
  ОТМЕНЕНА
}

Клиент "1" -- "0..*" Бронь : оформляет >
Камера  "1" -- "0..*" Бронь : относится к >
Бронь --> СтатусБрони

note right of Бронь::пересекается
  R2: Проверяется только
  против подтверждённых броней (R8).
end note

@enduml
```

## 3. Диаграмма последовательности — подача заявки

```plantuml
@startuml SequenceDiagram
autonumber
actor Клиент as C
participant "UI" as UI
participant "СервисБронирования" as S
participant "Камера" as Cam
participant "РепозиторийБроней" as R

C -> UI : податьЗаявку(камера, начало, конец)
activate UI
UI -> S : создатьБронь(клиент, камера, начало, конец)
activate S

S -> S : проверить корректность интервала\n(начало < конец)

alt интервал некорректен
  S --> UI : ошибка "Некорректный интервал"
  UI --> C : показать ошибку
else интервал корректен
  S -> R : найтиПодтвержденныеБрони(камера)
  activate R
  R --> S : List<Бронь>
  deactivate R

  S -> S : проверитьПересечение(интервал, брони)

  alt есть пересечение
    S -> S : создатьБронь(статус=ОТКАЗАНА, причина)
    S -> R : сохранить(бронь)
    S --> UI : отказ(причина)
    UI --> C : показать причину отказа
  else нет пересечения
    S -> S : создатьБронь(статус=ПОДТВЕРЖДЕНА)
    S -> R : сохранить(бронь)
    S --> UI : подтверждение(бронь)
    UI --> C : показать подтверждение
  end

end

deactivate S
deactivate UI

@enduml
```

## 4. Диаграмма состояний — жизненный цикл брони

```plantuml
@startuml StateDiagram
[*] --> Обрабатывается : подача заявки

state "Обрабатывается" as Processing

Processing --> Подтверждена : интервал корректен\nи нет пересечения
Processing --> Отказана : интервал некорректен\nили есть пересечение\n(указана причина)

state "Подтверждена" as Confirmed
state "Отказана" as Rejected
state "Отменена" as Cancelled

Confirmed --> Cancelled : клиент отменяет\n(запись сохраняется)
Confirmed --> Confirmed : блокирует интервалы\n(участвует в проверке пересечений)

Rejected --> [*] : сохранена как история
Cancelled --> [*] : сохранена как история\n(не блокирует интервал)

note right of Confirmed
  R2, R8: только подтверждённые
  брони участвуют в проверке
  пересечения интервалов.
end note

note right of Cancelled
  R8: отмена сохраняет запись,
  но интервал больше не блокируется.
end note

@enduml
```

Каждая диаграмма является самостоятельным PlantUML-блоком и отражает соответствующие требования R1–R8.
