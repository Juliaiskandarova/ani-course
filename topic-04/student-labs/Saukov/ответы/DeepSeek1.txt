Ниже — четыре отдельных полных блока PlantUML. Названия сущностей и статусов согласованы: **Бронь**, статусы **ПОДТВЕРЖДЕНА** и **ОТМЕНЕНА**. Отказ не создаёт **Бронь**.

## 1. Диаграмма вариантов использования

```plantuml
@startuml
left to right direction
skinparam packageStyle rectangle

actor "Клиент" as Client
actor "Сотрудник проката" as Employee

rectangle "Система бронирования камер" {
  usecase "Подать заявку\n(камера, начало, конец)" as UC_Submit
  usecase "Проверить корректность интервала\n(начало < конец)" as UC_ValidateInterval
  usecase "Проверить пересечение\nподтвержденных броней" as UC_CheckOverlap
  usecase "Создать подтвержденную бронь" as UC_Create
  usecase "Отказать с причиной" as UC_Refuse
  usecase "Просмотреть свои брони" as UC_MyBookings
  usecase "Отменить свою подтвержденную бронь" as UC_Cancel
  usecase "Просмотреть все брони" as UC_AllBookings
}

Client --> UC_Submit
Client --> UC_MyBookings
Client --> UC_Cancel
Employee --> UC_AllBookings

UC_Submit ..> UC_ValidateInterval : <<include>>
UC_Submit ..> UC_CheckOverlap : <<include>>
UC_Create .> UC_Submit : <<extend>> [нет пересечения]
UC_Refuse .> UC_Submit : <<extend>> [есть пересечение]

note right of UC_CheckOverlap
  Пересечение: начало < существующий.конец
  И существующий.начало < конец.
  Соприкосновение не пересечение (R7).
end note

note bottom of UC_Cancel
  Условие: клиент = владелец,
  статус = ПОДТВЕРЖДЕНА (R3).
  После отмены запись сохраняется,
  статус = ОТМЕНЕНА, интервал не блокируется (R8).
end note

note bottom of UC_Refuse
  При отказе Бронь не создается (R2).
end note
@enduml
```

## 2. Диаграмма классов

```plantuml
@startuml
title Диаграмма классов

enum СтатусБрони {
  ПОДТВЕРЖДЕНА
  ОТМЕНЕНА
}

class Клиент {
  ФИО
  почта
}

class Камера {
  серийныйНомер
  модель
}

class Бронь {
  начало
  конец
  статус : СтатусБрони
}

Клиент "1" -- "0..*" Бронь : оформляет >
Камера "1" -- "0..*" Бронь : относится к >
Бронь --> СтатусБрони

note right of Бронь
  R2: Бронь создается только как ПОДТВЕРЖДЕНА,
  если нет пересечения с ПОДТВЕРЖДЕНА.
  При отказе Бронь не создается.
  R8: ОТМЕНЕНА сохраняется и не блокирует интервал.
end note
@enduml
```

## 3. Диаграмма последовательности подачи заявки

```plantuml
@startuml
title Последовательность: подача заявки

actor "Клиент" as C

box "Система бронирования камер"
  participant "Система" as Sys
  database "Хранилище броней" as DB
end box

C -> Sys : Подать заявку(камера, начало, конец)
note right of C : Предусловие R7: начало < конец
activate Sys

Sys -> DB : Найти ПОДТВЕРЖДЕНА брони камеры
DB --> Sys : Список броней

Sys -> Sys : Проверить пересечение:\nначало < бронь.конец И бронь.начало < конец

alt есть пересечение с ПОДТВЕРЖДЕНА (R2)
  Sys -> C : Отказ с причиной: пересечение
  note right of Sys : Бронь не создается (R2)
else нет пересечения
  Sys -> DB : Создать Бронь(камера, клиент, начало, конец,\nстатус=ПОДТВЕРЖДЕНА)
  DB --> Sys : Бронь создана
  Sys -> C : Бронь подтверждена
end

deactivate Sys

note over C, Sys
  Соседние интервалы могут соприкасаться:
  пересечение строгое (R7).
  Отмена (R3,R8): только владелец и ПОДТВЕРЖДЕНА;
  статус -> ОТМЕНЕНА, запись сохраняется,
  отмененная бронь не блокирует интервал.
end note
@enduml
```

## 4. Диаграмма состояний брони

```plantuml
@startuml
title Диаграмма состояний брони

[*] --> ПОДТВЕРЖДЕНА : создана\n[R2: нет пересечения]
ПОДТВЕРЖДЕНА --> ОТМЕНЕНА : отменить()\n[клиент = владелец]
ОТМЕНЕНА --> [*] : запись сохранена (R8)

note right of ПОДТВЕРЖДЕНА
  Блокирует интервал.
  Создается только если нет пересечения
  с ПОДТВЕРЖДЕНА (R2).
end note

note right of ОТМЕНЕНА
  Не блокирует интервал (R8).
  Отмена сохраняет запись (R8).
end note

note bottom of ПОДТВЕРЖДЕНА
  Отказ при пересечении не создает Бронь (R2).
end note
@enduml
```

## Допущения

1. **Заявка** не моделируется как отдельная сохраняемая сущность: при отказе система возвращает причину, но запись **Бронь** не создаётся — это прямо следует из R2.
2. В диаграмме последовательности показано предусловие R7 «начало < конец»; отдельная обработка некорректного интервала не детализируется, чтобы не вводить новые правила.
3. Сотрудник проката не участвует в подаче заявки; по R4 он только просматривает все брони.
4. Отмена доступна только владельцу и только для статуса **ПОДТВЕРЖДЕНА**; после отмены статус — **ОТМЕНЕНА**, запись сохраняется.
5. Пересечение проверяется только с бронями в статусе **ПОДТВЕРЖДЕНА**; **ОТМЕНЕНА** не блокирует интервал. Соприкосновение интервалов не считается пересечением.

## Сопоставление R1–R8 с элементами диаграмм

| Требование | Где отражено |
|---|---|
| **R1** · Клиент подаёт заявку с камерой, началом и концом интервала | Use case `UC_Submit`; сообщение `C -> Sys : Подать заявку(камера, начало, конец)`; атрибуты `Бронь.начало`, `Бронь.конец`; связь с `Камера`. |
| **R2** · Если подтверждённая бронь той же камеры пересекает интервал — отказ с причиной; иначе создаётся подтверждённая бронь | Sequence `alt есть пересечение с ПОДТВЕРЖДЕНА` → `Отказ с причиной`, иначе → `Создать Бронь(... статус=ПОДТВЕРЖДЕНА)`; use cases `UC_CheckOverlap`, `UC_Create`, `UC_Refuse`; note у `Бронь` и состояния `ПОДТВЕРЖДЕНА`. |
| **R3** · Клиент видит свои брони и может отменить свою подтверждённую бронь | Use cases `UC_MyBookings`, `UC_Cancel`; переход `ПОДТВЕРЖДЕНА --> ОТМЕНЕНА : отменить() [клиент = владелец]`; note в sequence об отмене. |
| **R4** · Сотрудник проката видит все брони | Actor `Сотрудник проката` → `UC_AllBookings`. |
| **R5** · У камеры есть серийный номер и модель; у клиента — ФИО и почта | Классы `Камера` (`серийныйНомер`, `модель`) и `Клиент` (`ФИО`, `почта`). |
| **R6** · Каждая бронь относится к одной камере и одному клиенту; у камеры и клиента может быть несколько броней | Ассоциации: `Клиент "1" -- "0..*" Бронь`, `Камера "1" -- "0..*" Бронь`. |
| **R7** · Интервал корректен, если начало раньше конца; соседние интервалы могут соприкасаться | `UC_ValidateInterval`; note в sequence «Предусловие R7: начало < конец»; проверка пересечения строгими неравенствами; note «Соприкосновение не пересечение». |
| **R8** · Отмена сохраняет запись; отменённая бронь не блокирует интервал | Состояние `ОТМЕНЕНА` с note «Не блокирует интервал», «Отмена сохраняет запись»; note у `Бронь`; note в sequence. |

Проверка отказа: в ветке `alt есть пересечение` диаграммы последовательности нет вызова `Создать Бронь`; в note явно указано «Бронь не создается (R2)».
